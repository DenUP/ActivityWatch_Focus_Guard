# Focus Guard — Windows-программа с интерфейсом на localhost

**Версия v0.4.0.** Focus Guard — одно Windows-приложение `.exe`, которое живёт в системном трее, а управляется через красивую **локальную веб-страницу**, как ActivityWatch.

Никакого отдельного окна на панели задач. Нет расширений Chrome и нет новых отчётов. Во время учебной сессии приложение временно добавляет в системный файл `hosts` блокировку основных адресов YouTube.

## Использование

1. Скачай **новый** `ActivityWatchFocusGuard.exe` версии `v0.4.0` из [Releases](https://github.com/DenUP/ActivityWatch_Focus_Guard/releases). Старый EXE предыдущих версий содержит другой интерфейс.
2. Запусти EXE. Он появится **в системном трее Windows рядом с часами**, а в браузере откроется `http://127.0.0.1:8766/` (также можно открыть `http://localhost:8766/`).
3. Выбери **25, 40 или 60 минут** и нажми «Начать учебную сессию».
4. Windows запросит права администратора. После подтверждения будет создано задание восстановления и включена блокировка `hosts`.
5. Закрывай вкладку браузера, работай в университете или учись — Focus Guard остаётся в трее. **Двойной щелчок по значку в трее** или пункт «Открыть Focus Guard» открывает панель заново.
6. Для полного завершения программы используй пункт **«Выход»** в контекстном меню значка трея. Запущенное ранее ограничение сохраняется до запланированного окончания.

Порт **8766** используется только на локальном интерфейсе `127.0.0.1`; чужие устройства не смогут подключиться. Страница открывается из трея со случайным ключом доступа к управляющим действиям. Если набрать адрес вручную в новом браузерном профиле, состояние видно, но запуск и восстановление сессии недоступны — **открой страницу через значок в трее**.

Чтобы программа запускалась без автоматического открытия браузера, можно передать параметр `--tray-only` (для ярлыка автозагрузки). Когда понадобится интерфейс — открой его из меню трея.

## Что происходит с YouTube

- Учебная сессия отсчитывается по абсолютному времени; сворачивание окна и закрытие вкладки ничего не сбрасывают.
- Блокировка основных доменов YouTube реализована через Windows `hosts`, не через расширение браузера.
- Перед изменением `hosts` приложение создаёт задачу Планировщика Windows `ActivityWatchFocusGuard-Unblock`, работающую от `SYSTEM`, чтобы самостоятельно снять блокировку по окончании времени, даже если EXE закрыт или удалён.
- Если Планировщик не смог создать задачу, программа **не приступает** к изменению `hosts`.
- В панели есть **«Аварийно восстановить доступ»** с дополнительным подтверждением и запросом администратора.

**Ограничение:** `hosts` не поддерживает маски поддоменов. Уже открытое видео, некоторые альтернативные адреса, VPN, прокси и DNS-кэш могут обходить блокировку. После первого включения проверь сайты в своём браузере; иногда необходимо закрыть и снова открыть браузер. Поэтому это инструмент против привычного отвлечения, а не неуязвимый системный запрет.

## Если YouTube не разблокировался

Нажми «Аварийно восстановить доступ» в локальной панели и подтверди запрос Windows. Если EXE больше не запускается:

1. Открой Блокнот от администратора.
2. Открой файл `C:\Windows\System32\drivers\etc\hosts` (в диалоге выбери «Все файлы»).
3. Удали **только** строки между `# BEGIN ActivityWatchFocusGuard managed block` и `# END ActivityWatchFocusGuard managed block`, вместе с этими строками.
4. Сохрани файл, выполни от администратора `ipconfig /flushdns` и, если требуется, перезапусти браузер.
5. При необходимости удаляй только задачу Планировщика `ActivityWatchFocusGuard-Unblock`.

Никогда не удаляй весь `hosts`: в нём могут быть другие пользовательские настройки.

## ActivityWatch 0.14.1

ActivityWatch может работать параллельно. Главная панель Focus Guard показывает лишь **статус подключения** к ActivityWatch и ссылку на `http://127.0.0.1:5600/#/home`. Сам учебный таймер от ActivityWatch не зависит. Никакие данные о просмотренных страницах не отправляются в GitHub и не попадают в отдельные отчёты.

## Архитектура и безопасность

| Компонент | Назначение |
|---|---|
| `focus_guard.py` | Основной EXE, системный трей, открытие браузера, запрос UAC |
| `web_dashboard.py` | Локальный HTTP-сервер и защищённые API действия |
| `web/` | HTML, CSS, JS — работают офлайн, без внешних библиотек |
| `study_session.py` | Хранение абсолютного времени завершения |
| `system_block.py` | Точечная запись в `hosts` и задание восстановления Windows |

- Сервер слушает **только `127.0.0.1:8766`**.
- Изменяющие систему запросы требуют одновременно случайный токен, локальный `Origin`, ожидаемый `Host` и JSON. Межсайтовые запросы браузеров не допускаются. Случайный токен показывается странице через фрагмент URL и не отправляется при обычном HTTP-запросе.
- Программа использует лишь локальные Windows API; внешней телеметрии нет.
- Срок сессии хранится в `%PROGRAMDATA%\ActivityWatchFocusGuard\study_session.json`.
- Восстановление `hosts` удаляет только помеченный блок и не заменяет другие строки.

## Сборка EXE и публикация

GitHub Actions для этого репозитория пока отключены. Новый EXE необходимо собрать на Windows:

1. Скачай [исходники ZIP](https://github.com/DenUP/ActivityWatch_Focus_Guard/archive/refs/heads/master.zip) и распакуй.
2. Установи Python 3.11+ (рекомендуется 3.12).
3. Дважды щёлкни `build_windows.bat`. Он запустит тесты и соберёт один EXE со всеми файлами веб-интерфейса внутри.
4. В `dist` появятся `ActivityWatchFocusGuard.exe` и `SHA256SUMS.txt`. Загрузи их в новый выпуск с тегом **v0.4.0** через [Releases](https://github.com/DenUP/ActivityWatch_Focus_Guard/releases).

Для разработки: `py -3 -m unittest -v`. Для запуска из исходников сначала установи `py -3 -m pip install "pystray==0.19.5" "Pillow>=10,<13"`, затем выполни `py -3 focus_guard.py`. Готовому EXE Python не требуется.

**Первый запуск на Windows обязательно проверь на 25-минутной сессии**, особенно автоматическое восстановление доступа. Кодовые тесты не заменяют проверку Планировщика и кэша браузера на конкретной Windows-машине.
