# ActivityWatch Focus Guard v0.3 — одна программа для Windows

**Одна программа `.exe`, без расширения Chrome.** Во время учебной сессии Focus Guard добавляет временную блокировку основных адресов YouTube в системный файл Windows `hosts`. Работает в браузерах, использующих разрешение имён Windows. Новых отчётов нет.

Это инструмент для повышения сопротивления привычному отвлечению, **не защищённый от сознательного обхода**: пользователь с правами администратора может изменить `hosts`, использовать VPN/прокси или другое устройство. `hosts` не поддерживает маски поддоменов, а уже установленные браузерные соединения могут продолжить работать. Поэтому блокировка основных адресов YouTube не является стопроцентной блокировкой всех его сервисов.

## Установка и использование

1. Скачай **новый** `ActivityWatchFocusGuard.exe` версии **v0.3.0** в [Releases](https://github.com/DenUP/ActivityWatch_Focus_Guard/releases). Старый EXE версии 0.1/0.2 не умеет системную блокировку.
2. Запусти файл на Windows 10/11. ActivityWatch 0.14.1 можно оставить запущенным для дополнительного наблюдения, **но для самой блокировки он не обязателен**.
3. Нажми **«Начать 25 мин»**, **«Начать 40 мин»** или **«Начать 60 мин»**.
4. Windows покажет запрос UAC. Подтверди права администратора, чтобы программа могла изменить `hosts` и создать запланированное задание восстановления.
5. Проверь, что в программе написано **«Системная блокировка установлена»**. Закрой и заново открой вкладки YouTube; для уверенной проверки может потребоваться перезапустить браузер, поскольку у него есть кэш DNS и ранее установленные соединения.
6. После истечения времени Windows автоматически попытается восстановить исходное содержимое `hosts`, даже если Focus Guard закрыт. При выключенном компьютере задание настроено на запуск после пропущенного времени.

Крестик и сворачивание убирают окно в системный трей Windows, если значок трея доступен. Таймер продолжает отсчитываться по абсолютному времени и не сбрасывается при смене окна или закрытии EXE.

Если у тебя установлено **старое расширение** Focus Guard v0.2 в Chrome / Edge, удали его: новая версия им не пользуется, и оставшееся расширение может независимо блокировать YouTube по своему старому таймеру.

## Как безопасно восстанавливается доступ

Блокировка оформлена отдельным помеченным фрагментом в файле
`C:\Windows\System32\drivers\etc\hosts`. Программа не переписывает другие строки, кроме добавления и последующего удаления собственного фрагмента.

Перед изменением файла программа создаёт через **Планировщик заданий Windows** задачу `ActivityWatchFocusGuard-Unblock`, выполняемую от `SYSTEM` в установленное время. Её действие содержит самостоятельную процедуру удаления помеченного блока — **не требует работающего или существующего EXE**. Если Планировщик отклоняет создание задачи, программа не начинает блокировку. Задача использует настройку `StartWhenAvailable` для пропущенного времени запуска.

**Аварийное восстановление:** нажми в приложении «Аварийно восстановить доступ», подтверди запрос и UAC. Это намеренно не однокликовая отмена сессии.

Если EXE недоступен, а восстановление задания не произошло:

1. Открой Блокнот через «Запуск от имени администратора».
2. Открой файл `C:\Windows\System32\drivers\etc\hosts` (в диалоге выбери «Все файлы»).
3. Удали **только** строки между маркерами `# BEGIN ActivityWatchFocusGuard managed block` и `# END ActivityWatchFocusGuard managed block`, включая сами маркеры.
4. Сохрани файл и в терминале администратора выполни `ipconfig /flushdns`.
5. В «Планировщике заданий» при необходимости удали задачу `ActivityWatchFocusGuard-Unblock`.

Не удаляй и не заменяй весь файл `hosts`: в нём могут быть настройки других программ.

## Техническая реализация

- Запуск ограниченной по времени сессии: `study_session.py`.
- Безопасное изменение и восстановление `hosts`, создание задания: `system_block.py`.
- Экран управления, системный трей и необязательное чтение ActivityWatch API `http://127.0.0.1:5600/api/0/`: `focus_guard.py`.
- Срок сессии хранится в `%PROGRAMDATA%\ActivityWatchFocusGuard\study_session.json`. В нём нет адресов посещённых страниц или пользовательских отчётов.
- Старые всплывающие напоминания ActivityWatch по умолчанию отключены. Можно включить `"legacy_prompts_enabled": true` в `config.json`, однако они не управляют системным ограничением.

**Ограничения и проверка на реальной Windows.** Системная блокировка через `hosts` не создаёт wildcard-правил для всех видеосерверов `googlevideo.com`. Часть уже проигрываемых видео, DNS-over-HTTPS, прокси/VPN и альтернативные адреса могут обойти её. Мы не меняем настройки Secure DNS или VPN, не завершаем процессы браузеров, не устанавливаем драйверы и не запрещаем использовать компьютер. Полная совместимость с конкретной конфигурацией Windows, антивирусом и браузером требует испытания на твоём ПК.

## Сборка одного EXE

GitHub Actions для репозитория в настоящий момент недоступны; готовый EXE нужно собрать на Windows.

1. Скачай [исходники ZIP](https://github.com/DenUP/ActivityWatch_Focus_Guard/archive/refs/heads/master.zip) и распакуй.
2. Установи Python 3.11+ (рекомендуется 3.12) и запусти `build_windows.bat`.
3. Тесты выполнятся автоматически. В `dist` появятся `ActivityWatchFocusGuard.exe` и `SHA256SUMS.txt`.
4. Загрузи эти два файла в новый выпуск [Releases](https://github.com/DenUP/ActivityWatch_Focus_Guard/releases) с тегом **v0.3.0**.

Python нужен только для сборки. Конечным пользователям — один EXE и разрешение UAC при включении ограничения.

Проверить исходный код: `py -3 -m unittest -v`. Запустить из исходников: `py -3 focus_guard.py` (для трея: `py -3 -m pip install "pystray==0.19.5" "Pillow>=10,<13"`).

**Важный тест для первого запуска:** выбери 25 минут, проверь недоступность `youtube.com` и `youtu.be`, затем проверь, что доступ вернулся после завершения сессии. Если не вернулся, воспользуйся аварийным восстановлением. Не проверяй впервые перед экзаменом или другой важной работой.
